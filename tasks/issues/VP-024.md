## Результат задачи

Проверить весь lifecycle с активными uploads/downloads и закрепить правила стабильного состава.

## Критерии приёмки

- [ ] Нельзя publish при pending/processing/reservations; нельзя менять состав published.
- [ ] Unpublish закрывает новые download requests; уже начатый stream имеет явное документированное поведение.
- [ ] Ссылки в UI доступны только при реализованном download; повторные действия не приводят к гонкам.

## Проверка

Параллельные publish/confirm/unpublish/ZIP/delete, два пользователя, просроченный URL.

## Результат

Заполняется после реализации: изменения, выполненные проверки, ограничения.
