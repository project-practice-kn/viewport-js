# VP-035 — Приглашения, общий rate limit и ограничения загрузки

Статус: `done`\
Эпик: [EP07 — Проверка качества](../epics/EP07-quality.md)  
Зависимости: [VP-003](VP-003.md), [VP-010](VP-010.md), [VP-011](VP-011.md)

Исполнитель: Codex

## Результат задачи

Подготовить существующую регистрацию и прямые загрузки к демонстрации: регистрация только с invite из env, единый rate limit для HTML/API, размер PUT проверяет S3, лимиты по умолчанию — 10 МиБ на фотографию и 5 ГиБ на пользователя.

## Критерии приёмки

- [x] Поле кода приглашения есть при регистрации; HTML и API отклоняют неверный/отсутствующий код, при пустом env регистрация закрыта. Код не сохраняется в БД, page data и логах.
- [x] HTML-форма и API используют общий rate limit, возвращают 429/Retry-After; произвольные заголовки IP не обходят ограничение.
- [x] PUT подписывает Content-Length: S3 отклоняет другой размер, корректный файл загружается из браузера. Проверки confirm остаются.
- [x] Сервер, загрузчик, env и документация используют 10 МиБ / 5 ГиБ; существующие секреты и данные сохранены.
- [x] Verify, профильные тесты, реальный S3 smoke и браузерный сценарий проходят.

## Проверка

`npm test`, `npm run verify`, `docker compose --profile tools run --rm smoke`; браузер: invite, вход, загрузка JPEG/PNG/WebP, формы без JS. Проверить реальный S3 PUT с точным размером и изменением на ±1 байт.

## Результат

Выполнено 2026-10-31.

Добавлено поле кода приглашения. Before hook Better Auth проверяет `REGISTRATION_INVITE_CODE` для регистрации через HTML и API; сравнение выполняется через SHA-256 и timingSafeEqual. Неверный/отсутствующий код возвращает 403, пустая/шаблонная конфигурация — 503. Код не является полем пользователя и не возвращается в action data. `setup-env.mjs` генерирует отсутствующий код без вывода и сохраняет заданный код/существующие секреты.

HTML-форма вызывает HTTP handler Better Auth вместо `auth.api`: HTML/API делят штатный лимит три запроса за десять секунд на IP и auth path. IP определяется адаптером SvelteKit, внутренний заголовок перезаписывается, входные X-Forwarded-For не выбирают корзину лимитера. Ответы 429 содержат стандартный Retry-After; форма объясняет время повтора. Для reverse proxy в deployment описаны доверенный ADDRESS_HEADER и необходимость перезаписывать его на прокси.

PUT подписывает точный Content-Length и Content-Type. Браузер отправляет File с автоматически выставленной длиной; запрещённый для JS Content-Length не добавляется в requiredHeaders. Проверки HEAD/GET/Sharp остаются. Лимиты по умолчанию снижены до 10485760 / 5368709120 байт; обновлены загрузчик, env-пример, локальная конфигурация и документация. Данные и прежние секреты сохранены.

Проверки:

- `npm run verify` в Node.js 24 — типы без ошибок/предупреждений, форматирование и production build проходят.
- `npm test` — 10/10, включая границы размера/квоты, подписанные заголовки, invite, закрытую регистрацию без env, общий лимитер формы/API и подмену IP.
- `docker compose --profile tools run --rm smoke` — проходит: неверный invite не создаёт аккаунт, общий 429/Retry-After, реальный S3 отклоняет размер ±1 байт с 403 без создания объекта, корректные JPEG/PNG/WebP PUT/confirm и неизменность оригиналов по hash.
- Headless Chromium / Playwright — 18 проверок: неверный код и отсутствие кода/пароля в ответе формы, успешная регистрация с приглашением с JS и без JS, реальные загрузки подписанного размера, вход, редактор, публикация, скачивание и UI-регрессии; ошибок JS нет. На проверенных экранах 390/768/1440 px и в обеих темах axe нарушений не выявил.
- Изолированная проверка setup-env в Node.js 24: существующие настройки и секреты сохранены, отсутствующий invite сгенерирован без вывода.
- Compose пересобран с новым env, app/s3 healthy. Тестовые аккаунты, временные объекты и файлы проверок очищены в finally; зависимости и lockfile не менялись.

Ограничения: лимитер в памяти сбрасывается при перезапуске процесса; общий invite многоразовый и меняется через env с пересозданием контейнера. Общий расход диска включает временные объекты и превью сверх квоты оригиналов. Внешнее HTTPS-развёртывание остаётся в VP-029.
