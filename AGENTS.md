# Viewport — инструкции для агентов

## Перед работой

Прочитай README.md, docs/architecture.md и tasks/README.md. Для задачи из backlog прочитай её файл, родительский эпик и зависимости. Общение, документация и UI — на русском; идентификаторы и код — на английском.

AGENTS.md содержит постоянные правила работы с репозиторием. Не добавляй сюда отчёты о выполненной работе, списки готовых функций, состояние локального окружения, названия временных веток и этапы ревью. Статусы и результаты задач веди в tasks/, инструкции запуска и технические ограничения — в docs/.

## Запуск и проверка окружения

Порядок запуска — в [docs/deployment.md](docs/deployment.md). Используй Docker Compose; перед запуском проверь доступ к Docker daemon и свободные порты. Сохраняй существующие настройки `.env`, недостающие секреты генерируй без вывода в лог.

Проверяй HTTP-ответ приложения и состояние сервисов, прежде чем сообщать об успешном запуске. Чужие процессы не завершай. Не запускай второй сервер с той же SQLite. Не удаляй volumes и пользовательские данные без явного разрешения.

## Стек и архитектура

- Версии и совместимость определяются package.json и package-lock.json.
- Новые API сверяй с Context7, версии и peerDependencies — с npm registry. Не используй `--force` или `--legacy-peer-deps` для обхода несовместимости.
- Конфигурация SvelteKit — в vite.config.ts; импорты `#lib` указывают расширения; tsconfig наследует `$app/tsconfig`. Не копируй конфигурацию другой major-версии.
- Сохраняй один модульный монолит с SQLite и приватным S3. Не добавляй Redis, отдельные воркеры, брокеры, микросервисы или другой UI framework без согласования.
- Routes — тонкие load/actions/endpoints; бизнес-логика — src/lib/server; компоненты — src/lib/components.
- Серверные импорты не должны попадать в клиентский bundle.

## Данные и доступ

- Проверяй сессию и владельца в каждом защищённом load/action/endpoint; проверки layout недостаточно.
- Состав галереи изменяется только в draft. Публичные запросы проверяют token, published и принадлежность фотографии.
- Резервируй квоту атомарно в SQLite. Не выполняй сетевые операции внутри транзакции.
- Для операций SQLite + S3 предусматривай идемпотентность, компенсации и повторяемую очистку.
- S3 остаётся приватным. Ключи объектов генерирует сервер; содержимое файлов проверяется; оригиналы не изменяются.
- Не коммить и не логируй секреты, токены, подписанные URL и пользовательские данные.
- Не создавай неработающие кнопки и endpoints с фиктивным успешным результатом.

## Завершение работы

Выполняй проверки, соответствующие изменению; команды и их назначение описаны в [docs/verification.md](docs/verification.md). Для кода проверяй типы, форматирование и сборку через `npm run verify`. Для изменений данных, доступа или хранилища запускай соответствующие тесты.

После выполнения задачи обновляй её файл, эпик и индекс. Не ставь done по наличию пакета или каталога. Не редактируй lockfile вручную. Документация должна объяснять устройство и использование проекта; фактические результаты проверок записывай в задаче.
