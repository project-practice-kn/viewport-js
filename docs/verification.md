# Проверка приложения

## Автоматические проверки

Из корня репозитория:

```sh
npm ci
npm test
npm run verify
```

`npm test` использует временную SQLite и проверяет:

- повторяемость миграций, WAL/FK и ограничения целостности;
- владельца, валидацию полей, резервирование квоты и отмену;
- lifecycle, обложку, полный reorder и запрет изменения published;
- токены и безопасные имена файлов;
- Sharp: JPEG/PNG/WebP, EXIF-ориентацию, прозрачность, удаление метаданных, повреждённые/обрезанные файлы, MIME и pixel limit;
- подпись S3 URL с публичным endpoint независимо от внутреннего адреса.
- границы 10 МиБ / 5 ГиБ, подписанные Content-Length/Content-Type;
- invite для API, закрытую регистрацию без конфигурации, общий rate limit HTML/API и защиту от подмены IP-заголовков.

`npm run verify` последовательно проверяет Svelte/TypeScript, форматирование и production-сборку. Эти проверки не заменяют интеграцию с реальным S3.

## Интеграционный сценарий

Поднимите приложение по [инструкции](deployment.md), затем выполните:

```sh
docker compose --profile tools run --rm smoke
```

На Linux smoke использует host network, чтобы обращаться к опубликованным `localhost` URL. Для Docker Desktop требуется включённый host networking.

Smoke создаёт отдельные аккаунты и проверяет вход/выход, чужой доступ, HTML-формы, CSRF, CORS, приватность S3, загрузку трёх форматов, повторный и конкурентный confirm, гонку за квоту, повреждённый файл, очистку, обложку/порядок, публикацию и скачивание. SHA-256 скачанного оригинала сравнивается с исходником. После unpublish проверяются 404 страницы и скачивания. Тестовые записи и объекты удаляются в finally. Не запускайте smoke одновременно с другим экземпляром smoke.

Smoke использует `REGISTRATION_INVITE_CODE` только из окружения, не выводя его. Проверяются отказ HTML-регистрации с неверным приглашением, общий 429/Retry-After для HTML/API и попытка подменить IP заголовками. PUT с размером на один байт больше/меньше подписанного должен получить 403 от S3, объект не должен появиться. После срабатывания auth rate limit подождите десять секунд перед следующим smoke или ручным входом с того же IP.

При запуске приложения на хосте с соответствующими DATABASE_PATH и S3_ENDPOINT можно использовать `npm run test:smoke`. Эта команда работает с БД из окружения; не направляйте её на другую БД, чем у проверяемого сервера.

## Проверка в браузере

1. Зарегистрируйтесь с кодом приглашения из `.env`, выйдите и войдите повторно. Неверный код не создаёт аккаунт, код отсутствует в HTML и page data ответов. Неверный пароль должен отклоняться; кабинет без сессии перенаправляет на вход. После трёх попыток за десять секунд вход/регистрация с того же IP и auth path возвращают 429 с понятным временем повтора. Кнопка глаза показывает и скрывает пароль без отправки формы и потери текста.
2. Создайте галерею, сохраните настройки и обновите страницу. Второй аккаунт не должен видеть её в своём списке или получать доступ к редактору.
3. Загрузите JPEG/PNG/WebP и дождитесь ready. Проверьте прогресс, сообщение ошибки, отмену и повтор одного файла. Передача 100% сама по себе ещё не означает готовность фотографии.
4. Выберите обложку и измените порядок. После reload результат должен сохраниться. Проверьте кнопки с клавиатуры и на узком экране.
5. Опубликуйте галерею и откройте ссылку в приватном окне. Проверьте обложку, порядок, тему, отсутствие требования входа и скачивание оригинала.
6. Снимите публикацию и обновите страницу клиента: ожидается 404. Ранее выданный S3 URL может действовать до истечения 120 секунд.
7. Проверьте формы и публичную страницу без JavaScript. Для прямого загрузчика JavaScript необходим.

Дополнительно для UI/UX:

- Проверьте экраны на ширинах 390/768/1440 px с длинными названиями галерей и файлов. Горизонтальной прокрутки быть не должно; на телефоне ссылки «Фотографии» и «Настройки и публикация» переходят к нужному разделу редактора.
- Во время отправки формы кнопка показывает ход операции и блокирует повторную отправку. Ошибка входа сохраняет введённые данные. В редакторе измените поля, смените обложку и порядок: ввод должен сохраниться, в том числе после предыдущей ошибки валидации. Публикация доступна после сохранения настроек и завершения загрузки.
- Выберите три файла, отмените ещё ожидающий файл и повторите его после завершения партии. Проверьте отдельные стадии передачи и обработки, итог партии и повтор после сетевой ошибки. При попытке уйти во время загрузки можно остаться; переходы между разделами редактора не прерывают загрузку.
- Скопируйте публичную ссылку кнопкой. При запрете Clipboard API поле должно получить фокус и выделение для ручного копирования. Без JavaScript ссылка также доступна в поле.
- Пройдите элементы клавишей Tab: первая ссылка пропускает шапку, фокус виден, поле выбора файлов и кнопки доступны с клавиатуры. Проверьте светлую и тёмную галерею и режим reduced motion. Автоматический аудит axe-core дополняет ручную проверку.
- Откройте отсутствующую страницу: ожидаются HTTP 404, русское объяснение и рабочая ссылка на главную.

## Проверка контейнеров и сохранности данных

```sh
docker compose ps
curl --fail http://localhost:5173/health
```

Ожидаются healthy у app/s3 и `{"status":"ok"}` от приложения. После создания аккаунта, галереи и загрузки файлов выполните:

```sh
docker compose down
docker compose up --build -d --wait
```

Повторный вход, галерея и скачивание должны работать с прежними данными. Для сравнения файлов можно использовать `sha256sum` исходника и скачанного оригинала. Не добавляйте `-v` к down: он удаляет volumes.

## Границы покрытия

Smoke моделирует прерывание сохранённым processing и S3-объектами до ready commit, а отказ DELETE — через fault injection. Это не проверка всех возможных моментов SIGKILL и сетевых обрывов. Полная матрица отказов, измерение ресурсов и публичное HTTPS-развёртывание описаны в задачах [VP-026](../tasks/issues/VP-026.md), [VP-028](../tasks/issues/VP-028.md) и [VP-029](../tasks/issues/VP-029.md). Фактические результаты прогонов и оставшиеся ограничения записываются в соответствующей задаче.
