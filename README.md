# Viewport

Сервис передачи фотографий: фотограф регистрируется, создаёт галерею, загружает JPEG/PNG/WebP, публикует ссылку; клиент без аккаунта смотрит превью и скачивает неизменённый оригинал.

Стек: Node.js 24 или 26, SvelteKit 3 / Svelte 5, TypeScript 6, Bulma + CSS, SQLite / Drizzle, Better Auth, приватный S3 и Sharp. Сервер работает одним процессом; Docker использует Node.js 24.

## Запуск в Docker

```sh
node scripts/setup-env.mjs
docker compose up --build -d --wait
```

Открыть **http://localhost:5173**. В Docker работают production-приложение и приватный SeaweedFS 4.48. Миграции SQLite, создание bucket и CORS выполняются автоматически перед стартом. Оба сервиса имеют healthcheck; приложение работает пользователем node. Данные сохраняются в volumes `app-data` и `s3-data` после перезапуска и пересоздания контейнеров.

Node.js на хосте нужен только для однократной генерации `.env`; вариант этой команды тоже через Docker есть в [инструкции запуска](docs/deployment.md). Существующие настройки и секреты скрипт сохраняет, новые секреты не выводит в лог.

Для TrueNAS с существующим Traefik и доменом `https://calendar.samuraj.su:4443` используйте отдельный [compose.truenas.yaml](compose.truenas.yaml) и [пошаговый гайд](docs/truenas.md). Он не объединяется с локальным Compose; app и приватный S3 маршрутизируются через Docker labels.

```sh
docker compose ps
docker compose logs --tail=50 app
docker compose restart
docker compose down
```

`down` сохраняет данные; `down -v` удаляет volumes. Полный интеграционный сценарий в Docker на Linux:

```sh
docker compose --profile tools run --rm smoke
```

Для разработки с автоматическим обновлением после изменений:

```sh
docker compose -f compose.yaml -f compose.dev.yaml up --build -d --wait
```

Этот режим использует существующие данные. Подробности и вариант разработки на хосте — в [docs/deployment.md](docs/deployment.md).

## Как пользоваться

1. На странице входа выбрать «Создать аккаунт», заполнить имя, email, пароль (10–128 символов) и код приглашения от организатора. Код задаётся в `REGISTRATION_INVITE_CODE` в `.env`; `setup-env.mjs` генерирует его при первом запуске без вывода в лог.
2. В кабинете создать галерею. Настроить название, описание и светлую/тёмную тему, сохранить настройки.
3. Выбрать фотографии, проверить размер очереди и свободное место, нажать «Начать загрузку» и дождаться статуса «Готово». Новые файлы можно добавлять во время передачи; неподходящие отмечаются отдельно. Нажать на снимок, чтобы открыть просмотрщик, или скачать оригинал в редакторе. Порядок выбора сохраняется; доступны сортировка по имени, массовое перемещение и удаление выбранных фотографий с подтверждением. Первый готовый снимок в порядке выбора становится обложкой; её можно выбрать вручную, в том числе после публикации, без изменения порядка снимков и клиентской ссылки.
4. Проверить закрытый «Предпросмотр для клиента», затем опубликовать галерею, нажать «Скопировать ссылку» и отправить её клиенту. Проверить ссылку можно в приватном окне. Если копирование браузером недоступно, нажать на поле ссылки и скопировать выделенный адрес вручную. Действие «Сменить ссылку» отзывает старую ссылку и выдаёт новую.
5. Открыть фотографию в просмотрщике и скачать оригинал или скачать все готовые фотографии ZIP-архивом. Архив доступен клиенту и владельцу в редакторе, в том числе в черновике. Регистрация клиенту не нужна.
6. Снять публикацию: новые запросы страницы и скачивания получат 404. Для изменения состава, настроек или удаления опубликованной галереи сначала снять публикацию. Обложку можно менять без снятия публикации.
7. Чтобы удалить черновик вместе со всеми снимками, подтвердить удаление в редакторе. После недавней загрузки может понадобиться дождаться истечения её резерва (по умолчанию до 30 минут); при ошибке хранилища повторить удаление.

Формы регистрации, входа, редактирования и публикации, публичная страница и скачивание работают без JS. Прямой загрузчик требует JS. У него две одновременные передачи, прогресс, отмена и повтор отдельного файла.

После прерывания загрузки откройте редактор: серверные состояния сохраняются. Уже переданный файл можно проверить повторно; непереданный — выбрать заново, старый резерв отменить. Истёкшие резервы очищаются при открытии редактора. Ссылки на превью обновляются автоматически; несохранённые настройки защищены предупреждением при уходе. В клиентской галерее сначала показаны 24 снимка; кнопка загружает следующие, а без JavaScript открывает следующую страницу. В кабинете доступны обложки, поиск, фильтр статуса, сортировка по дате, названию и размеру, а также быстрые ссылки. Дата после загрузки страницы показывается в часовом поясе браузера. В настройках аккаунта можно сменить пароль; восстановление через организатора описано на странице «Забыли пароль?» и в [инструкции обслуживания](docs/deployment.md).

## Проверки

```sh
npm test
npm run verify
# При работающих приложении и S3:
npm run test:smoke
npm run uploads:cleanup
```

`npm test` проверяет SQLite, ограничения, доступ, lifecycle, сортировку и Sharp на временной БД. `verify` — типы, форматирование, сборку. `test:smoke` проверяет полный сценарий через HTTP и реальный S3, конкурентную квоту, приватность, CORS, повторы, ошибки очистки и хэши трёх форматов. Созданные тестовые аккаунты, БД-записи и S3-объекты удаляются в `finally`. При запросах загрузки также выполняется штатная очистка истёкших резервов, а временные объекты удалённых галерей повторно проверяются в фоне. Если новых загрузок нет, периодически запускайте эту очистку при остановленном приложении по [инструкции](docs/deployment.md). Не запускайте smoke параллельно сам с собой.

Команды и покрытие проверок: [docs/verification.md](docs/verification.md). Архитектура: [docs/architecture.md](docs/architecture.md). Статусы: [tasks/README.md](tasks/README.md).

## Ограничения

План развития ведётся в [backlog](tasks/README.md). Подписанные GET действуют 120 секунд; уже выданная ссылка сохраняет доступ до истечения TTL после unpublish или смены ссылки галереи. С JavaScript превью обновляются в редакторе и публичной галерее; без JavaScript для получения новых ссылок обновите страницу. Старые снимки без отдельной миниатюры используют прежнее крупное превью. Файлы очереди не сохраняются между закрытиями вкладки; серверные состояния загрузок сохраняются.
