# Viewport

Локальный MVP передачи фотографий: фотограф регистрируется, создаёт галерею, загружает JPEG/PNG/WebP, публикует ссылку; клиент без аккаунта смотрит превью и скачивает неизменённый оригинал.

Стек: Node.js 24, SvelteKit 3 / Svelte 5, TypeScript 6, Bulma + CSS, SQLite / Drizzle, Better Auth, приватный S3 и Sharp. Один серверный процесс; отдельного worker нет.

## Запуск

```sh
nvm install
nvm use
npm ci
node scripts/setup-env.mjs
npm run db:migrate
docker compose up -d --wait s3
npm run s3:setup
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Открыть **http://localhost:5173**. Скрипт настройки создаёт `.env` и случайные auth/S3 секреты без вывода в лог, сохраняя существующие настройки. Для npm native modules могут потребоваться Python 3, make, C++ compiler. Нужны доступ к Docker daemon и свободные порты 5173/8333.

Если Docker недоступен, можно запустить официальный бинарный SeaweedFS 4.48 на loopback:

```sh
SEAWEEDFS_BINARY=/путь/к/weed npm run s3:local
```

Далее в другом терминале выполнить `npm run s3:setup` и `npm run dev`. Данные бинарного S3 сохраняются в `data/s3`, SQLite — в `data/viewport.db`. Полная инструкция и остановка: [docs/deployment.md](docs/deployment.md).

## Демонстрация checkpoint

1. На странице входа выбрать «Создать аккаунт», заполнить имя, email и пароль (10–128 символов).
2. В кабинете создать галерею. Настроить название, описание и светлую/тёмную тему.
3. Выбрать до 20 файлов за раз, дождаться статуса «Готово». Первый снимок автоматически становится обложкой; обложку и порядок можно изменить кнопками.
4. Опубликовать галерею и открыть ссылку из редактора в приватном окне.
5. Посмотреть фотографии и нажать «Скачать оригинал». Регистрация клиенту не нужна.
6. Снять публикацию: новые запросы страницы и скачивания получат 404. Для редактирования опубликованной галереи сначала снять публикацию.

Формы регистрации, входа, редактирования и публикации, публичная страница и скачивание работают без JS. Прямой загрузчик требует JS. У него две одновременные передачи, прогресс, отмена и повтор отдельного файла.

## Проверки

```sh
npm test
npm run verify
# При работающих приложении и S3:
npm run test:smoke
npm run uploads:cleanup
```

`npm test` проверяет SQLite, ограничения, доступ, lifecycle, сортировку и Sharp на временной БД. `verify` — типы, форматирование, сборку. `test:smoke` проверяет полный сценарий через HTTP и реальный S3, конкурентную квоту, приватность, CORS, повторы, ошибки очистки и хэши трёх форматов. Созданные тестовые аккаунты, БД-записи и S3-объекты удаляются в `finally`; имеющиеся галереи не затрагиваются. Не запускайте smoke параллельно сам с собой.

Протокол и границы проверки: [docs/verification.md](docs/verification.md). Архитектура: [docs/architecture.md](docs/architecture.md). Статусы: [tasks/README.md](tasks/README.md).

## Граница реализации

Реализованы VP-002, 003, 005–007, 009–018 и 021. ZIP, удаление готовых фотографий/галерей, lightbox, production deployment и backup/restore остаются в backlog. Подписанные GET действуют 120 секунд; уже выданная ссылка сохраняет доступ до истечения TTL после unpublish. Если долго открытая страница перестала показывать превью, обновите её.
